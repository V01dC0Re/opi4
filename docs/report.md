# Лабораторная работа #4

## Реализованные MBean

Домен MBean: `com.github.itmovalesnikov.web3`.

1. `type=PointsStatistics`
   - `TotalPoints` - общее количество установленных точек.
   - `MissedPoints` - количество точек, не попавших в область.
   - `ConsecutiveMisses` - максимальная текущая серия промахов среди активных пользователей.
   - `reset()` - сброс счетчиков.
   - Notification `com.github.itmovalesnikov.web3.fourMisses` отправляется, когда один пользователь совершает 4 промаха подряд.

2. `type=Area`
   - `Radius` - текущий радиус `R`.
   - `Area` - площадь фигуры при текущем радиусе.

Площадь вычисляется по формуле:

```text
S = R^2 / 4 + pi * R^2 / 16 + R^2 / 2 = ((12 + pi) / 16) * R^2
```

## Выявленная проблема производительности

В исходной версии `PointsBean.getPoints()` при каждом получении списка точек выполнялся вывод каждой точки в стандартный поток вывода:

```java
points.forEach((p) -> {
    System.out.println(p.getX() + " " + p.getY() + " " + p.getSessionId());
});
```

JSF вызывает getter при построении страницы. Поэтому при росте таблицы результатов приложение выполняло лишний обход списка и синхронный консольный вывод во время рендеринга страницы. В профилировщике это проявляется как лишняя нагрузка на поток обработки HTTP-запроса и вызовы `PrintStream.println`.

## Устранение проблемы

Отладочный вывод удален из `PointsBean.getPoints()`. Метод теперь только получает данные текущей сессии из базы и возвращает их в таблицу.

## Алгоритм локализации

1. Запустить приложение и открыть страницу ввода точек.
2. В VisualVM открыть CPU Sampler для JVM сервера приложений.
3. Нажать `CPU`.
4. Несколько раз добавить точки, чтобы таблица результатов стала больше.
5. Остановить семплирование.
6. В результатах найти активный HTTP worker thread сервера приложений.
7. Раскрыть стек вызовов рендеринга JSF.
8. Найти повторяющиеся вызовы `PointsBean.getPoints()` и `PrintStream.println`.
9. Удалить отладочный вывод.
10. Повторить профилирование и сравнить результаты.
