# Проверка выполненной работы

Инструкция не привязана к конкретному расположению проекта на компьютере. Все команды выполняются из корня репозитория `opi4`.

## 1. Требования к окружению

Нужно установить:

- JDK 17;
- Maven 3.8+;
- сервер приложений с поддержкой Jakarta EE, например WildFly, Payara или совместимый Tomcat с нужными библиотеками;
- JConsole, обычно входит в JDK;
- VisualVM.

Проверка версий:

```bash
java -version
mvn -version
```

Ожидаемо, что Java имеет версию 17.

## 2. Сборка проекта

Из корня проекта выполнить:

```bash
mvn clean test
mvn package
```

После успешной сборки WAR-файл будет находиться в:

```text
target/web3.war
```

## 3. Запуск приложения

1. Запустить сервер приложений.
2. Развернуть `target/web3.war`.
3. Открыть приложение в браузере по адресу, который выдал сервер.

Пример для локального сервера:

```text
http://localhost:8080/web3/
```

Точный адрес может отличаться в зависимости от сервера приложений.

## 4. Проверка MBean статистики точек

1. Запустить приложение и открыть страницу ввода точек.
2. Запустить JConsole:

```bash
jconsole
```

3. Подключиться к JVM сервера приложений.
4. Перейти на вкладку `MBeans`.
5. Найти домен:

```text
com.github.itmovalesnikov.web3
```

6. Открыть MBean:

```text
type=PointsStatistics
```

7. Проверить атрибуты:

- `TotalPoints`;
- `MissedPoints`;
- `ConsecutiveMisses`.

8. В браузере отправить несколько точек.
9. Обновить значения в JConsole.

Ожидаемый результат:

- `TotalPoints` увеличивается после каждой отправленной точки;
- `MissedPoints` увеличивается только после промаха;
- `ConsecutiveMisses` показывает текущую серию промахов.

## 5. Проверка уведомления о 4 промахах подряд

1. В JConsole открыть:

```text
com.github.itmovalesnikov.web3:type=PointsStatistics
```

2. Перейти в раздел `Notifications`.
3. Нажать `Subscribe`.
4. В приложении отправить 4 точки подряд, которые не попадают в область.
5. Проверить, что в JConsole появилось уведомление типа:

```text
com.github.itmovalesnikov.web3.fourMisses
```

## 6. Проверка MBean площади фигуры

1. В JConsole открыть MBean:

```text
com.github.itmovalesnikov.web3:type=Area
```

2. Проверить атрибуты:

- `Radius`;
- `Area`.

3. В приложении выбрать `R = 1` и отправить точку.
4. Обновить MBean в JConsole.

Ожидаемая площадь для `R = 1`:

```text
0.946349...
```

5. Выбрать `R = 2` и отправить точку.
6. Обновить MBean.

Ожидаемая площадь для `R = 2`:

```text
3.785398...
```

Формула:

```text
S = ((12 + pi) / 16) * R^2
```

## 7. Проверка количества загруженных классов

1. В JConsole перейти на вкладку `Classes`.
2. Найти значение `Loaded Classes` или `Current classes loaded`.
3. Зафиксировать это значение для отчета.

## 8. Проверка графиков MBean в VisualVM

1. Запустить VisualVM.
2. Подключиться к JVM сервера приложений.
3. Открыть вкладку `MBeans`.

Если вкладки `MBeans` нет, установить соответствующий плагин через `Tools -> Plugins`.

4. Найти:

```text
com.github.itmovalesnikov.web3
```

5. Добавить на график атрибуты:

- `TotalPoints`;
- `MissedPoints`;
- `ConsecutiveMisses`;
- `Area`.

6. В браузере отправлять точки.

Ожидаемый результат:

- график `TotalPoints` растет после каждой отправки;
- график `MissedPoints` растет после промахов;
- график `Area` меняется после отправки точки с другим радиусом.

## 9. Проверка CPU-профилирования

1. В VisualVM открыть вкладку `Sampler` или `Profiler`.
2. Выбрать режим `CPU`.
3. Нажать `Start`.
4. В браузере выполнить типовой сценарий:

- выбрать координаты;
- отправить точку;
- повторить несколько раз;
- обновить таблицу результатов.

5. Нажать `Stop`.
6. В результатах найти поток с самым большим процентом CPU.

Обычно при активной работе с веб-интерфейсом это HTTP worker thread сервера приложений, например:

```text
http-nio-8080-exec-...
```

Точное имя зависит от используемого сервера.

## 10. Проверка исправления проблемы производительности

В исходной версии в методе `PointsBean.getPoints()` был отладочный вывод точек через `System.out.println`. В выполненной работе он удален.

Проверка:

1. Открыть файл:

```text
src/main/java/com/github/itmovalesnikov/web3/bean/PointsBean.java
```

2. Убедиться, что в методе `getPoints()` нет вызова:

```java
System.out.println(...)
```

3. Запустить CPU-профилирование в VisualVM.
4. Добавить много точек через приложение.
5. Проверить, что в горячих участках выполнения нет массовых вызовов:

```text
PrintStream.println
```
